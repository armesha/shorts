# Shorts Factory UI redesign research

Дата исследования: 2026-06-17.

Цель: переработать панель так, чтобы она работала как операционный центр для каналов, генерации, паков, нарезок, уведомлений и админки. Сейчас данных много, но поток работы размазан по страницам.

## Выводы из референсов

Linear: меньше визуального шума, строгая иерархия, плотная навигация, панели вместо длинных страниц. Для нас это значит: не делать все страницы одинаковыми карточками, а разделить список и детали.

Vercel: проект виден через последнее состояние, превью, статус, activity. Для нас это значит: у канала должна быть карточка с аватаром, очередью, ближайшим запуском, ошибкой, последним шортсом и быстрыми действиями.

Buffer: главный объект - workspace публикаций. Есть All Channels view, статусы queue/drafts/approvals/sent, фильтр по каналам. Для нас это значит: нужен один операционный экран "очередь и публикации", а не только отдельные "История" и "Каналы".

Plausible: аналитика понятна за минуту: верхние метрики, один график, кликабельные фильтры, раскрытие деталей. Для нас это значит: `/statistics` должен начинаться с 4-6 главных метрик и одного графика, а не сразу смешивать платформу, публикации, фильтры и таблицу.

YouTube Studio: дашборд строится из карточек "важное", "последний контент", "аналитика", "уведомления", "идеи". Для нас это значит: стартовый экран должен показывать, что требует внимания сегодня.

Supabase: навигация должна быть контекстной: организация/проект отдельно, пользователь всегда доступен сверху, уведомления сгруппированы. Для нас это значит: текущий длинный sidebar надо сгруппировать по рабочим зонам, а админские пункты спрятать в отдельную группу.

Later: медиа-библиотека работает через фильтры, теги, usage state, side library. Для нас это значит: `clip-demos` должен стать медиатекой нарезок с быстрым просмотром, фильтрами по паку/дате/типу/длительности и side-панелью выбранного ролика.

## Главные проблемы текущего интерфейса

1. Sidebar длинный и все пункты выглядят одинаково важными. Админские, рабочие и системные разделы смешаны.

2. Нет единого "сегодня надо сделать вот это". Пользователь должен сам зайти в статистику, каналы, ошибки, паки и историю.

3. `/statistics` перегружен: вкладки, две кнопки обновления, платформа, KPI, график публикаций, фильтры, аналитика и таблица идут одним потоком.

4. `/studio` выглядит как форма, но задача там пошаговая: выбрать канал/пак, выбрать режим, сгенерировать, проверить превью, сохранить/добавить в очередь.

5. `/clip-demos` уже полезный, но это пока просто сетка видео. Для 150+ роликов нужна медиатека: фильтры, "новые", просмотр, выбранный ролик, быстрые действия.

6. `/users` смешивает создание аккаунта, отправку уведомления и огромную матрицу доступов. На мобильном это особенно тяжело.

7. Мобильный UI в целом работает, но primary actions иногда упираются в край, таблицы и длинные формы слишком быстро становятся вертикальной простыней.

## Предлагаемый новый каркас

### Навигация

Слева оставить sidebar, но сгруппировать:

- Работа: Обзор, Каналы, Студия, Очередь, Нарезки
- Контент: Паки, Карточки, Шаблоны
- Контроль: Статистика, Уведомления, Ошибки
- Админ: Пользователи, Система, Обновления, Настройки

Верхняя панель:

- глобальный поиск / command palette
- активный пользователь или режим импersonation
- уведомления
- язык
- быстрые действия: "Создать", "Обновить данные", "Добавить канал"

На мобильном: короткий topbar + bottom navigation для 4-5 главных разделов: Обзор, Каналы, Студия, Нарезки, Еще.

### Новый стартовый экран: "Обзор"

Сделать как operational cockpit:

- строка состояния: Google key, YouTube quota/API, scheduler, errors
- "Требует внимания": каналы без OAuth, паки меньше N дней, ошибки публикации, Analytics API disabled
- "Сегодня": опубликовано, запланировано, в очереди, ближайший запуск
- "Каналы под риском": список из 5 с lowest stock days
- "Последние шортсы": 6-8 последних с превью
- "Быстрые действия": пополнить пак, создать нарезку, обновить YouTube Data, открыть ошибки

Текущий `/statistics` можно оставить как "Аналитика", а `/` сделать настоящим обзором. Если важно оставить `/statistics` стартовым, внутри него первым табом должен быть "Мои каналы" и короткий operational header.

### Каналы

Перейти от обычной сетки к master-detail:

- слева/в центре список каналов с avatar, статусом, queue days, uploads/day, next run, last error
- справа sticky-панель выбранного канала: расписание, пак, OAuth, статистика, последние ролики, действия
- быстрые фильтры: "мало контента", "ошибки", "не подключены", "сегодня публикуют"

Карточки каналов должны быть плотнее: меньше текста, больше статусных индикаторов. Расписание лучше показывать одной строкой chips, а полный список - в detail drawer.

### Студия

Сделать рабочий bench:

- левая колонка: выбор канала/пака/режима, запасы, язык, источник
- центр: параметры генерации, фон, стиль, очередь, кнопка генерации
- правая sticky-колонка: 9:16 preview, статус генерации, последние 3 результата

Для video-pack режима показывать не текстовую форму, а "выбрать видео из пака / случайный клип / добавить в библиотеку".

Большой select паков заменить на searchable combobox с группами: встроенные, кастомные, видео-паки, текстовые.

### Нарезки

Сделать media library:

- верх: pack tabs/chips с количеством и "новые за сегодня"
- фильтры: пак, дата добавления, длительность, голос, только новые
- сортировка: новые/старые/длительность/title
- карточка ролика: вертикальное превью, title, createdAt, duration, pack, voice, кнопки preview/download/copy path
- клик открывает side panel или modal viewer с большим плеером и метаданными

Для 150+ роликов подключить virtual grid, иначе страница будет тяжелеть.

### Паки

Сделать inventory board:

- верх: "сколько дней осталось" вместо только "сколько карточек"
- low-stock секция первой
- встроенные и кастомные - табами
- карточка пака: total, used, posted, available, days left, used by channels
- действие: "пополнить" / "инструкция генерации" / "открыть карточки"

### Админка

Разделить на вкладки:

- Пользователи
- Доступ к пакам
- Уведомления
- Имперсонация / вход под пользователем
- Лимиты и нагрузка

Матрицу доступов делать как таблицу со sticky first column, sticky header, горизонтальным скроллом, batch actions и поиском по пользователю/паку.

### Ошибки и уведомления

Ошибки должны работать как issue inbox:

- группировка одинаковых ошибок уже есть, развить ее
- показывать affected accounts/users
- quick action: отправить уведомление владельцу, открыть канал, открыть справку
- для админа: глобальный inbox, для пользователя: только свои уведомления

## Переходы и состояния

Минимум анимаций, но больше ясности:

- route transition: короткий fade/slide 120-180ms
- side drawer для деталей канала, ролика, ошибки
- skeleton для KPI, графиков и видео-сетки
- optimistic toast после действий
- sticky action bar на мобильном для основной кнопки
- подтверждения только для destructive actions

Не делать декоративные hero-блоки, большие градиенты или лишние карточки внутри карточек. Это рабочий dashboard.

## Что добавить в стек

Сейчас стек React + Tailwind + DaisyUI + Recharts нормальный. Next.js не нужен для этой задачи.

Рекомендуемые добавления:

- `@tanstack/react-query` - кеш, refetch, loading/error state, invalidation после действий.
- `@tanstack/react-table` - нормальные таблицы для Users, Errors, History, Stats.
- `@tanstack/react-virtual` - виртуализация для clip gallery, history, больших матриц.
- `cmdk` - command palette: найти канал, пак, ролик, пользователя, действие.
- `sonner` или свой toast layer - единые уведомления об успешных/ошибочных действиях.

Опционально:

- View Transitions API через CSS/небольшой helper вместо тяжелой motion-библиотеки.
- `date-fns` для единых дат, если текущих форматтеров станет мало.

Не добавлять сразу:

- новый роутер
- Next.js
- тяжелый charting suite вместо Recharts
- отдельный state manager, пока React Query закрывает server state

## План внедрения

   - сгруппированный sidebar
   - topbar с search/notifications/profile
   - mobile bottom nav
   - единые page headers и toolbar

2. Обзор:
   - новый operational dashboard
   - блок "требует внимания"
   - быстрые действия

3. Каналы:
   - compact channel list
   - right detail drawer
   - filters by health

4. Студия:
   - трехколоночный workbench
   - searchable pack combobox
   - sticky preview

5. Нарезки:
   - media library layout
   - side panel viewer
   - virtualized grid

6. Админка:
   - вкладки
   - table engine

7. QA:
   - Playwright screenshots для desktop 1440x1000 и mobile 390x844
   - canvas/video nonblank checks для нарезок

## Первый практический шаг

Начинать лучше не с цветов, а с shell + overview. После этого остальные страницы можно переносить по одной, не ломая текущие API.

Первый PR/итерация:

- добавить новый `AppShell`
- сгруппировать навигацию
- добавить topbar
- оставить существующие страницы внутри нового контейнера
- сделать `/` обзором "что требует внимания"
- сохранить `/statistics` как аналитику с текущей логикой

Это даст ощущение нового продукта без риска сразу переписывать Studio, Users и ClipDemos.
