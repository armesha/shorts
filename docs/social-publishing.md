# Общие каналы YouTube, Instagram и TikTok

Все площадки находятся в общем разделе `/channels`. При добавлении канала пользователь выбирает площадку, затем получает подходящий способ подключения: YouTube через Google OAuth, Instagram и TikTok через собственные cookies. Каждый канал имеет отдельные подключение, библиотеку, расписание, очередь и историю. Можно подключить несколько каналов одной площадки; cookies и задания между ними не смешиваются.

В карточке подключения Instagram/TikTok поддерживаются загрузка файла `.json` или `.txt` и вставка текста. Форматы: JSON-экспорт браузера, Playwright storageState, Netscape cookies.txt и строка Cookie. После сохранения нужно нажать «Проверить вход». Приложение не импортирует cookies из соседних проектов. Проверка открывает площадку в отдельном браузерном контексте и определяет аккаунт. Наличие файла само по себе не означает успешного подключения. Challenge, CAPTCHA и повторный вход пользователь проходит в своём браузере, затем экспортирует cookies заново.

Cookies находятся в игнорируемой папке `data/social-private/sessions/` (0700 на папку, 0600 на файлы), отдельно для пары владелец/канал. Ответы API содержат только статус, имя аккаунта и время проверки. Замена cookies и отключение отменяют ожидающие задания только данного канала. При отключении файл сессии удаляется. Владелец управляет своими каналами; основной суперадминистратор получает доступ через общий контроль доступа к каналам.

Готовые MP4 отправляются из библиотеки соответствующего канала через общую кнопку публикации или по расписанию. Добавление задания резервирует ролик атомарно, чтобы ручная отправка и планировщик не отправили его одновременно. Очередь работает в основном API-сервисе с интервалом 10 секунд; задания сохраняются в SQLite. Для задания создаётся отдельная приватная копия MP4. Удаление исходника после постановки в очередь не ломает отправку. После завершения или отмены копия удаляется. Дневной предел соответствует лимиту владельца на один канал, учитывает ожидающие и подтверждённые задания по UTC-дню отправки и не требует Google-ключа.

Отправка выполняется через браузерный редактор площадки. Статус `published` появляется только после подтверждения с идентификатором публикации. История записывается в общую историю канала с площадкой и ссылкой на публикацию. После успеха обычный ролик удаляется из библиотеки; для включённой функции бесконечных паков возвращается в конец очереди с сохранением исходных файлов. Ошибка до нажатия Post/Share снимает резервирование и позволяет повторить отправку. Если результат после нажатия неизвестен или сервис перезапущен во время отправки, статус меняется на `needs_review`, а резервирование сохраняется без автоматического повтора. После проверки профиля владелец может явно подтвердить отсутствие публикации и разрешить новую попытку.

Существовавшие подключения из прежнего раздела `/social` переносятся на старте сервера в отдельные каналы вместе с файлами сессий и заданиями. Перенос повторяемый и сохраняет прежние снимки медиа; он не изменяет счётчики роликов других каналов. Старые API по площадке поддерживают только случай одного уже созданного канала этой площадки и не создают каналы скрыто.

Браузерные интерфейсы площадок могут меняться. Реальная проверка подключения и публикации требует свежих cookies пользователя. Автоматические тесты используют искусственные сессии и имитацию площадок; живые аккаунты и реальные публикации в них не используются.

Проверки: `npm run typecheck`, `npm test`, `npm run web:build`, `npm run creator:web:build`. После изменения серверного кода нужен `npm run server:restart`.

Creator работает отдельной службой `shorts-creator.service` на 127.0.0.1:8091. Публичный прокси направляет `/creator`, `/creator/*` и `/api/creator/*` в этот сервис, остальные маршруты Shorts — на :8080. Обе веб-сборки нужны для обновления ссылок в основном приложении и Creator.

Основа браузерной отправки: [TikTok Studio](https://support.tiktok.com/en/using-tiktok/creating-videos/creator-tools-on-tiktok) и [публикация видео как Instagram Reels](https://about.fb.com/news/2022/07/new-ways-to-create-instagram-reels-remix/).
